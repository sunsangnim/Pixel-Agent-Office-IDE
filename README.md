# Pixel Agent Office IDE

Claude Code, Codex CLI, Antigravity CLI를 픽셀 오피스 안의 팀으로 표현하는 Electron 기반
멀티 에이전트 IDE입니다. 명령을 채팅으로 보내면 작업 규모와 `@` 멘션 여부에 따라 담당
팀장을 선택하고, 실제 CLI 세션의 상태를 책상·회의실·탕비실·출입구에 반영합니다.

## 주요 기능

- Claude, Codex, Antigravity 팀장 3명과 팀별 하위 세션 4명, 총 15개 고정 좌석
- 미지정 작업은 Claude 기본 배정, `@코덱스 ...` 같은 직접 멘션은 해당 팀장에게 단독 배정
- 복합 작업은 Claude=코딩·문서작업, Codex=이미지 생성, Antigravity=테스트·검증으로 분담
- 팀장별 최대 4개 하위 세션과 전체 동시 Run 6개 제한
- 등록된 직원(`AgentProfile`)과 실제 PTY 프로세스(`AgentRun`) 분리
- 미출근, 좌석 대기, 작업, 승인 대기, 오류, 회의실, 탕비실 상태와 이동 애니메이션
- Claude/Codex/Antigravity별 출력 인식 어댑터와 세션별 실패 격리
- 터미널 드릴다운, 채팅 지시, CLI 템플릿 설정 및 로그인 터미널
- 독립 PNG 배경·가구·캐릭터 레이어로 구성한 16/32-bit풍 픽셀 오피스
- 유리 탕비실과 회의실, 긴 회의 테이블·둘레 의자·상석 노트북, 파티션으로 나눈 비중첩 15석 레이아웃
- 창·해상도에 맞춰 전체를 자동 축소하는 3:2 확장 오피스와 팀 영역에 겹치지 않는 우측 김태호 대표실
- 원목 상판·모니터·키보드·마우스·중앙 의자로 구성한 단일 SVG 픽셀 데스크와 한 칸짜리 탕비실 유리문
- 베젤·화면 반사·키캡·상판 측면·하드 섀도를 갖춘 픽셀 데스크와 통합형 탕비실 전면 유리벽
- 기존 대비 절반 폭의 픽셀 대표실, 전면 유리 패널·유리문·소파·화분·사이드 테이블
- 우측 하단 사분면에 배치된 대표실과 일반 사무실로 연결되는 왼쪽 유리 출입문
- 오피스 외곽에서 8px 이상 안쪽에 고정된 대표실과 좌측 상단 문·중앙 데스크·하단 양쪽 인테리어
- 충돌 화분을 제거한 `office-background-v3`와 회의실 원본 문 유지·탕비실 단독 복제 구조
- `@` 입력 시 멤버 목록형 자동완성과 입력창 내부 멘션 칩
- 평일 근무시간 자동 출근, 엘리베이터·탕비실·회의실 문 동작, 휴식·회의 체크포인트·업무 복귀를 포함한 생활형 오피스
- 대표 1명, 세 팀 15명, 확장 슬롯 4명으로 구성된 20인 고유 회사원 픽셀 캐릭터 세트
- 회의 발언 기록, 질문마다 세 팀장의 개별 답변, 종료 후 통합 SRS 한 건 작성
- 설정창에서 대표·직원·확장 슬롯 20명을 한 화면에 확인하는 5×4 캐릭터 검수 그리드

## 실행

Node.js, Git, GitHub CLI(`gh`)와 사용할 에이전트 CLI를 설치하고 각 CLI 로그인을 먼저 완료합니다.
새 작업의 비공개 저장소 생성에는 `gh auth login --hostname github.com`으로 로그인한 계정을 사용합니다.

```bash
npm install
npm run dev
```

설정 창에서 각 템플릿의 실행 명령과 작업 폴더를 환경에 맞게 지정할 수 있습니다. 실제 CLI는
작업이 배정될 때 지연 실행되며, 빈 좌석을 표시하기 위해 프로세스를 미리 실행하지 않습니다.

## 작업 라우팅

| 입력 유형 | 배정 |
| --- | --- |
| 담당자 미지정, 가벼운 작업 | Claude 팀장 1명 |
| `@클로드`, `@Claude`, `@코덱스`, `@Codex`, `@안티그래피`, `@Antigravity` | 멘션된 팀장 |
| 병렬·전체·아키텍처·마이그레이션·통합 테스트 등 복합 작업 | 3개 팀 오케스트레이션(Claude=코딩·문서작업, Codex=이미지 생성, Antigravity=테스트·검증) |

하위 세션은 미출근 또는 대기 상태에서 시작해 작업이 배정되면 빈 책상에 앉습니다. 작업 완료
후에는 슬롯 정책에 따라 좌석, 탕비실 또는 회의실로 이동합니다. 부모 Run 취소 시 자식 Run도
정리하며 중첩 깊이는 2단계로 제한합니다.

채팅 입력창에서 `@`를 입력하면 에이전트 자동완성 목록이 표시됩니다. 한글·영문 이름과 영문
대소문자를 모두 지원하며, 여러 팀을 함께 멘션하면 해당 팀들을 복합 작업으로 배정합니다.

앱 재시작 시 15개 직원 프로필과 좌석 구성은 코드에서 다시 생성됩니다. 실행 중이던 외부 CLI
프로세스는 복구하지 않으며, Run이 없는 직원은 안전하게 `offDuty` 상태로 표시됩니다.

## 새 작업과 저장소

새 작업을 요청하면 `바탕화면/오피스 IDE 작업실/프로젝트/<작업 ID>/`에 독립된 Git 저장소를 만들고,
로그인한 GitHub 계정에 `office-task-<날짜>-<고유 ID>` 이름의 **비공개 저장소**를 생성합니다.
`origin` 연결과 `main` 초기 커밋 푸시를 마친 뒤 에이전트에 작업을 배정합니다.
IDE 소스 저장소와 기존 작업 저장소는 재사용하지 않습니다. SRS·개발 기록은 작업실의 별도 문서 폴더에 남습니다.

한 작업의 팀장과 사원은 공용 `feature/<작업 ID>` 작업본 하나를 공유합니다. 각 Phase 검증이 끝나면
Git 담당 한 명이 추가 확인 없이 feature에 커밋·푸시하고, 모든 Phase와 인수 조건이 완료된 뒤에만
최신 main 반영·재검증 → `--no-ff` 병합 → main 푸시를 수행합니다. 기획 승인은 계속 대표가 결정합니다.
세션을 종료해도 공용 작업본과 미커밋 변경은 보존합니다. 자세한 절차는 [운영정책](OPERATING_POLICY.md)을 따릅니다.

회의를 마쳐 새 기획을 만들 때도 작업별 저장소를 생성합니다. 빈 회의는 저장소를 만들지 않습니다.
로그인·네트워크 문제로 생성이 중단되면 **프로젝트 이어가기**에서 해당 작업을 선택하거나 회의 SRS 작성을
재시도하세요. 저장된 저장소 이름을 사용하므로 재시도나 재실행으로 원격 저장소가 중복 생성되지 않습니다.

## 프로젝트 이어가기

IDE를 완전히 종료했다가 열면 채팅 기록을 비우고, 이전 CLI 대화를 재사용하지 않습니다.
시작 화면에서는 저장된 작업 목록만 확인합니다. 프로젝트 문서를 읽거나 에이전트를 자동으로
실행하지 않습니다. 같은 실행 안에서 화면만 새로고침하면 현재 채팅은 유지됩니다.

`테트리스 하자`, `오목 이어서 하자`처럼 저장된 프로젝트를 지정하거나 **프로젝트 이어가기**를
누르면 해당 프로젝트만 인수인계합니다. `계속하자`처럼 대상이 불분명하면 프로젝트 선택창을
표시합니다. 새 세션은 통합 SRS → 개발 기록 → 최근 Git 커밋과 미커밋 변경을 확인한 뒤
남은 작업을 진행합니다. 승인 대기 중인 기획은 승인 대기로 돌아오며 자동으로 구현하지 않습니다.

작업별 `DEVELOPMENT-LOG.md`는 전용 작업실의 `산출물/문서/<작업>/`에 저장합니다.
에이전트에는 각 명령·작업 및 검증 결과를 기록하도록 지시하고, IDE는 완료 보고의 변경 파일,
검증 결과, 남은 일과 Git 상태를 덧붙입니다. 완료 보고가 없는 작업은 미완료로 남겨 둡니다.
프로젝트 전환 시 기존 작업본을 보존하며, 다른 프로젝트를 작업 중인 세션은 전환하지 않습니다.

## 회의와 SRS

`회의하자`로 부장·차장·과장만 모인 뒤 채팅에 요구사항을 말하면 한 회의의 기록으로 누적합니다.
사원은 기존 업무를 유지하며, 상석은 대표 전용입니다.
질문이나 의견 요청에는 Claude·Codex·Antigravity의 실제 CLI가 각각 답변하며, 채팅과 캐릭터 대화창에
표시합니다. 자동으로 질문으로 인식되지 않는 문장은 **세 에이전트에게 질문** 버튼으로 보낼 수 있습니다.

`회의 끝` 또는 **회의 끝내고 SRS 작성**을 누르면 남은 답변을 기다린 뒤 Claude가 발언 전체를 하나의
SRS·PRD·화면설계로 정리합니다. 뒤에 나온 정정·취소를 반영하고, 에이전트의 제안과 대표의 결정을
구분하도록 지시합니다. 기획을 승인하기 전에는 구현하지 않습니다. 빈 회의에서는 문서를 만들지 않습니다.

회의 기록은 화면 새로고침이나 재실행 후에도 남습니다. 재실행 시 답변 세션을 자동으로 시작하지 않으며,
미완료 답변은 **답변 다시 받기**로 이어갑니다. CLI가 실패하면 해당 에이전트만 재요청하고, 이미 받은
답변과 회의 기록을 보존합니다. 정상 답변을 받기 전에는 회의 SRS 작성을 완료 처리하지 않습니다.

## 개발 및 검증

캐릭터는 기본적으로 자기 자리에서 대기합니다. 60~180초 대기 후 한 명씩 가끔 탕비실에
들러 도착 후 8~15초 쉬고 돌아옵니다. 업무나 회의 지시가 오면 그 지시를 우선하며,
이동 경로가 막히면 제자리에서 걷지 않고 대기합니다. 인테리어 편집 중에는 이동과 휴식
시간이 멈추고, 편집 종료 후 변경된 배치에 맞춰 재개합니다.

```bash
npm run typecheck
npm run test:movement
npm run test:editor-layering
npm run test:integration
npm run test:recovery
npm run build
npm run test:recovery-ui
npm run test:meeting-ui
```

통합 테스트는 유료 API나 로그인된 실제 에이전트를 호출하지 않습니다. 로컬 가짜 CLI를 실제
`node-pty`로 실행해 라우팅, 15개 프로필, 어댑터 신호, 정상 완료, 오류 감지와 세션 격리를
검증합니다.

이동 검사는 실제 씬의 상태·경로·도착 처리기를 사용해 반복 상태 갱신, 장애물, 통로 대기,
자동 휴식과 복귀, 회의, 편집 중 정지를 검증합니다. 통합 검사 종료 시에는 PTY를 명시적으로
정리하고 Node의 비동기 정리가 끝날 때까지 기다립니다.

## 프로젝트 구조

- `src/main` — Electron 메인 프로세스, PTY·IPC·CLI 어댑터·Run 관리
- `src/preload` — context-isolated IPC 브리지
- `src/renderer` — React 채팅, 오피스, 프로필, 터미널 UI
- `src/shared` — 프로필·Run·정책·공유 타입
- `scripts` — 비용 없는 PTY 통합 테스트 하네스
- `tasks` — 작업별 SRS·PRD·화면설계, PHASES, 최종 결과 문서

전체 구현 이력은 [PHASES.md](./PHASES.md)에서 확인할 수 있습니다. 생활형 오피스와 20인
캐릭터 세트의 최종 검증 결과는 각각
[Phase 37 결과](./tasks/phase-37-living-agent-office/README.md),
[Phase 38 결과](./tasks/phase-38-corporate-character-roster/README.md)에 기록되어 있습니다.

## 현재 제한사항

- 실제 Claude/Codex/Antigravity 동작은 설치 버전, 로그인 상태와 각 CLI 출력 형식에 영향을 받습니다.
- 실행 중인 외부 CLI 프로세스와 대화 컨텍스트는 앱 재시작 후 자동 재연결하지 않습니다.
- 이미지 자산이 번들 용량의 큰 비중을 차지하므로 배포 단계에서 무손실 최적화를 권장합니다.
