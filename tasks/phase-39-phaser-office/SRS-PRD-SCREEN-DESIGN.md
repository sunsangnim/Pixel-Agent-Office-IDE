# Phase 39 Phaser 생활형 오피스 — SRS · PRD · 화면설계

## 목표

정적 DOM/CSS 오피스를 Phaser 3 기반 2D 게임 장면으로 교체한다. 실제 CLI/PTY 실행은 Electron main이 계속 담당하며, 게임 장면은 직렬화된 에이전트 상태만 받아 이동·착석·업무·휴식·회의를 표현한다.

## 필수 요구사항

- 바닥, 벽, 방, 문, 가구, 캐릭터를 독립 게임 오브젝트로 구성한다.
- 모든 월드 좌표는 16px 타일 그리드를 기준으로 한다.
- 캐릭터는 벽과 가구를 통과하지 않고 경로 노드를 따라 이동한다.
- 캐릭터 렌더 깊이는 발 위치의 y좌표를 기준으로 갱신한다.
- `offDuty`, `arriving`, `deskIdle`, `walking`, `working`, `pantry`, `meeting`, `requestingHelp`, `error` 상태를 게임 상태 머신으로 관리한다.
- 문은 `closed`, `opening`, `open`, `closing` 상태와 독립 문짝 애니메이션을 가진다.
- 의자는 접근점·착석점·방향·전면 레이어를 가지며 착석 시 위치를 스냅한다.
- 탕비실 냉장고·커피머신·간식, 회의실 의자, 대표실 소파와 상호작용한다.
- 행동 중에는 action lock을 적용하고 완료 이벤트 후 다음 상태로 전환한다.
- CLI 오류나 게임 렌더 오류가 서로의 프로세스를 종료시키지 않는다.
- 앱 재시작 시 직렬화 가능한 월드 상태를 복구한다.

## 아키텍처

`Electron main(PTY/CLI) → React 상태 브리지 → Phaser OfficeScene`

- React는 채팅·설정·터미널·프로필과 에이전트 상태 계산을 담당한다.
- Phaser는 월드 렌더링, 게임 루프, 이동, 충돌, 애니메이션, 상호작용을 담당한다.
- 두 계층은 `OfficeWorldSnapshot`과 `OfficeWorldEvent`만 교환한다.

## 화면 레이어

1. 바닥 타일
2. 러그·바닥 장식
3. 벽·방 배경
4. 가구 후면
5. 캐릭터와 이동 오브젝트(y-sort)
6. 가구 전면·문틀
7. 말풍선·상태 UI
