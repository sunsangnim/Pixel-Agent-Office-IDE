# Phase 37 생활형 에이전트 오피스 — SRS · PRD · 화면설계

## 1. 제품 목표

CLI 프로세스 상태를 단순 아이콘으로 표시하지 않고, 에이전트가 출근하고 문을 통과하며 자기 자리에서 일하고 휴식·회의 후 업무로 복귀하는 생활형 픽셀 오피스로 표현한다.

## 2. 기능 요구사항

### 출퇴근과 근무시간

- 시스템 로컬 시간(Asia/Seoul 환경의 OS 시간)을 분 단위로 동기화한다.
- 평일 오전 08:00 이상 오후 17:00 미만은 근무시간이다.
- 근무시간에는 세 팀장이 CLI 실행 여부와 무관하게 출근 상태로 표시된다.
- 출근 캐릭터는 엘리베이터 문 열림 → 문 안에서 등장 → 자기 데스크 이동 순서를 따른다.
- 근무시간 밖이며 실행 세션이 없는 팀장은 미출근으로 돌아간다.

### 문 상호작용

- 엘리베이터·탕비실·회의실 문은 접근 중 `opening`, 통과 중 `open`, 통과 후 `closing` 상태를 가진다.
- 캐릭터는 벽을 통과하지 않고 정의된 출입문 경유점으로 이동한다.

### 탕비실

- 탕비실 에이전트는 `snacking` 또는 `drinking` 행동을 번갈아 수행한다.
- 캐릭터 위 말풍선과 작은 소품으로 간식·음료 행동을 표시한다.
- 탕비실 벽면에 OS 시간과 동기화된 픽셀 아날로그 시계를 표시한다.

### 회의

- “회의하자”, “회의 시작”, “다 모여” 요청은 전체 회의 명령으로 처리한다.
- 실행 중 세션은 종료하지 않는다.
- 각 실행 세션의 최근 작업·PTY 버퍼 위치를 회의 체크포인트로 보존하고 UI 전송을 잠시 보류한다.
- 참석 가능한 모든 출근 에이전트가 회의실 문을 통과해 빈 의자에 한 명씩 착석한다.
- 회의 종료 시 이전 상태와 데스크로 복귀하고 보류된 작업을 계속한다.

### 업무

- `working`, `requestingHelp`, `error` 상태 캐릭터는 자신의 팀·슬롯 데스크 위치에 있어야 한다.
- 작업 중에는 착석 포즈와 모니터 작동 상태를 표시한다.

### 대표실

- 의미 불명확한 기존 장식을 제거한다.
- 픽셀 화분, 책장, 소파, 사이드 테이블, 러그, 서류·스탠드 등 용도가 명확한 가구로 정돈한다.
- 가구는 문 이동 경로와 겹치지 않는다.

## 3. 상태 모델

`offDuty → arriving → deskIdle ↔ working`

`deskIdle/working → pantryDoor → pantry(snacking|drinking) → pantryDoor → deskIdle/working`

`deskIdle/working → meetingCheckpoint → meetingDoor → meeting(seated) → meetingDoor → previousState`

문 상태: `closed → opening → open → closing → closed`

## 4. 세션 보존 정책

- 회의 진입은 `kill` 또는 인스턴스 삭제를 호출하지 않는다.
- 실제 OS 프로세스 강제 정지는 CLI 안전성이 확인되지 않으면 사용하지 않는다.
- UI 수준의 `meetingHold`로 신규 프롬프트 전송을 보류하고 기존 프로세스/PTY는 유지한다.
- 체크포인트에는 인스턴스 ID, 이전 presence, 최근 업무 문구, 회의 시작 시각을 저장한다.
- 회의 종료 후 체크포인트를 제거하고 이전 presence로 복원한다.

## 5. 화면설계

- 엘리베이터 문짝은 중앙에서 좌우로 열리고 닫힌다.
- 탕비실·회의실 유리문은 픽셀 프레임 안에서 슬라이드된다.
- 회의 좌석은 테이블 둘레 8개 좌표로 분산한다.
- 탕비실 시계는 상단 벽면의 비어 있는 영역에 배치한다.
- 캐릭터 행동은 상태 class와 `data-*` 속성으로 시각화한다.
