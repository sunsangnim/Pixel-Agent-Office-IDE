# 문서 우선 오케스트레이션 운영정책 — SRS · PRD · 화면설계

## PRD

- 모든 작업을 독립 폴더와 명시적인 문서에서 시작한다.
- 에이전트 미지정 시 Claude를 기본 담당으로 사용한다.
- 직접 호명된 팀장은 하위 세션 사용을 자율 결정한다.
- 큰 작업은 사용자에게 분업 계획을 알린 뒤 여러 팀으로 분배한다.
- Phase마다 검증, 문서 갱신, 커밋·푸시를 수행한다.

## SRS

- 작업 전 `tasks:prepare` IPC가 통합 기획서, Phase 문서, README 초안을 원자적으로 준비한다.
- 문서 준비 실패 시 CLI 실행 및 프롬프트 전송을 차단한다.
- 작업 폴더명은 타임스탬프와 안전하게 정제된 요청 제목으로 생성한다.
- 명시적 에이전트 호명은 난이도 자동 분류보다 우선한다.
- 자동 라우팅 기본값은 Claude이며 복합 작업만 세 팀을 호출한다.

## 화면설계

- 채팅 스레드에 작업 폴더와 기획 문서 생성 완료 이벤트를 표시한다.
- 자동 분배 전에 담당 및 분업 근거를 시스템 메시지로 표시한다.
- 기존 직접 선택 수신자 UI는 유지하고 최우선으로 처리한다.

- [x] 에이전트 프롬프트에 Phase별 커밋·푸시와 최종 README 의무가 포함된다.
