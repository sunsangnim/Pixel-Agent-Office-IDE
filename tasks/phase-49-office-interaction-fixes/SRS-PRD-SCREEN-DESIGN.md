# Phase 49 — Office interaction fixes (SRS/PRD/화면설계)

## 배경

사용자가 실행 중인 화면을 직접 확인하고 스크린샷에 7개 항목을 지적했다. 원인
조사 결과 각 증상은 코드 상의 구체적 결함으로 귀결되었다.

## 요구사항 (사용자 원문 기준)

1. 캐릭터가 목적지로 이동할 때 좌우로 헤매지 않고 자연스럽게 걸어가야 한다.
2. 인테리어 편집으로 데스크 위치를 옮기면 담당 에이전트가 옮겨진 자리를 찾아가야 한다.
3. 업무 중인 캐릭터는 자기 데스크의 의자 스냅포인트에 앉아야 한다.
4. 팀장은 근무시간(08:00-17:00, 평일)에는 항상 출근 상태를 유지하며, 배정된
   업무가 없을 때는 탕비실(간식/음료), 자기 데스크, 회의실 중 한 곳에 있어야
   한다.
5. 엘리베이터 문은 실제 문처럼 벽에 자연스럽게 박혀 있어야 한다.
6. 영역(footprint) 충돌 회피로 인해 의자/데스크가 서로 멀어지거나, 노트북이
   테이블에 가려 편집기에서 선택되지 않는 문제가 없어야 한다.
7. 최상단 벽 장식이 방 경계에서 끊기지 않고 자연스럽게 이어져야 한다.

## 원인 분석 요약

- A* 목적지가 자기 자신의 가구 충돌 영역 안에 있을 때(의자 스냅포인트가 의자
  충돌 박스 내부에 있는 것이 정상) 경로탐색이 실패해 장애물 회피 없는 직선
  이동으로 폴백 → 벽/가구 모서리를 따라 미끄러지며 좌우로 흔들리는 것처럼 보임.
- 캐릭터 이동 목표가 정적 `TEAM_DESKS` 좌표를 참조해, 편집기에서 옮긴 실제
  의자 위치와 무관하게 고정되어 있었음.
- `useOfficePresence`에서 팀장의 유휴 상태가 `deskIdle`로 하드코딩되어 있었고,
  PTY가 `exited`되면 근무시간에도 `offDuty`로 전환되었음.
- 엘리베이터 문 그래픽이 장식 벽 밴드(y 26-90)보다 아래(y 94-150)에 위치해
  방 한가운데 떠 있는 것처럼 보였음.
- 데스크·의자가 서로의 충돌 영역을 침범해 배치 시 충돌 회피 로직이 발동,
  전체 맵 좌상단부터 훑는 방식이라 먼 곳으로 재배치될 수 있었음.
- `addFurniture`의 `depth` 매개변수가 `initial.y ?? depth`라는 죽은 코드로
  인해 항상 무시되어, 노트북에 준 명시적 상위 depth가 적용되지 않았음.
- 최상단 장식 벽이 방 3개(탕비실/회의실/출입구)별로 나뉜 3개 타일로 그려져
  경계마다 이음새 틈이 생겼음.

## 화면설계 변경

- 엘리베이터 문: 위치 (820, 94) 크기 84×112 → 위치 (820, 58) 크기 84×64로
  변경, 장식 벽 밴드에 맞춤. 관련 웨이포인트도 `elevatorInside`(820,115→80),
  `elevatorExit`(820,225→130)로 조정.
- 최상단 장식 벽: 3개 분리 타일(x=144/480/808, 각각 폭 256/352/272) → 폭
  960(전체 실내 폭)의 단일 연속 타일로 통합.
